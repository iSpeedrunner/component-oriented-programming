Мета. Навчитися завантажувати реальні дані з зовнішнього API за допомогою хуків useState і useEffect, use, коректно обробляти стани завантаження та помилок, а також виводити й сортувати дані у вигляді таблиці/списку.

Загальний опис. Продовжуємо дашборд із ЛР1. Тепер mock-дані замінюємо на реальні дані з API вашого варіанту. Ви додаєте головний віджет дашборду — таблицю (або список) з даними, яка завантажується при монтуванні компонента, показує індикатор завантаження, коректно реагує на помилки й дозволяє сортувати записи. KPI-картки з ЛР1 тепер теж рахуються з реальних даних.

Завдання.

Завантаження даних. Через useEffect виконайте запит до API свого варіанту при першому рендері. Отриманий масив збережіть у стані через useState.

Стани запиту. Реалізуйте умовний рендеринг трьох станів: loading (поки вантажиться), error (запит не вдався), empty (даних немає).

Таблиця/список даних. Виведіть записи у вигляді таблиці або списку карток (мінімум 4–5 значущих полів відповідно до варіанту).

Сортування. Сортування щонайменше за двома полями (напр. за назвою та числовим показником) з перемиканням напрямку. Реалізується як derived state — без мутації вихідного масиву.

Живі KPI. Перерахуйте KPI-картки з ЛР1 на основі реальних даних.

Вимоги.

Дані завантажуються лише через useEffect.
Логіка доступу до даних відокремлена від представлення (container / presentational).
Сортований масив — похідний; оригінал не мутується.
Кожен запис має коректний key.
Опрацьовані всі три стани (loading / error / empty).
КОП-практики. Ізоляція side-effects у useEffect · життєвий цикл (монтування) · поділ container / presentational · separation of concerns · умовний рендеринг станів · derived state (сортування) · імутабельність · key у списках.

Критерії оцінювання.

Дані з API через useEffect у стані — 2
Таблиця/список (≥4–5 полів) — 2
Стани loading / error / empty, KPI з реальних даних — 1
Сортування за ≥2 полями з напрямком (derived state) — 1
Чистота коду, розділення логіки й в'юхи, key, імутабельність — 2
